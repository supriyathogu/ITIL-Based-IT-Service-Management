# Change Enablement

## Definition
Change Enablement aims to maximise successful service and product changes by assessing risks, authorising changes appropriately, and managing the change schedule.

## Why it matters
Changes to infrastructure, applications, network settings, or security controls can introduce service disruption. A controlled approach helps teams understand risk, dependencies, approvals, and implementation plans.

## Typical change record information
- Change description and reason.
- Services and configuration items affected.
- Risk and impact assessment.
- Implementation plan.
- Test and validation plan.
- Backout or recovery plan.
- Required approvals.
- Planned schedule and communications.
- Post-implementation review.

## Example
A proposed change to a VPN gateway configuration should be assessed, authorised, scheduled, tested, and reviewed according to the organisation's change policy.

## Project boundary
This repository documents the practice and example only. It does not claim that a production change was submitted, approved, or implemented.
