# Ticket Workflow

## Purpose
A workflow defines the statuses a work item can move through and the transitions that allow those changes.

## Status concepts
| Status or label | General meaning |
|---|---|
| Open | Ticket has been logged and is awaiting handling |
| Work in Progress | A support person is actively working on the ticket |
| Pending | Work is waiting for information, action, or an external dependency |
| Resolved | A solution or restoration has been recorded |
| Closed | Ticket handling is complete |
| Cancelled | Ticket is no longer being pursued |

These are general descriptions. The actual statuses and transitions available in Jira must be verified in the project.

## Good transition practice
- Confirm the ticket is ready for the selected transition.
- Complete required fields marked with an asterisk.
- Use an internal note for support-team updates not intended for the requester.
- Use a customer reply only when an actual user-facing response is intended.
- Record factual actions and avoid claiming tests or fixes that did not happen.
