# Incident Resolution Reports

## Purpose
A resolution report records how an incident was handled, what restored service, and whether follow-up is required.

## Recommended report fields
- Ticket key.
- Incident summary.
- Date reported and date resolved.
- Affected service.
- Impact and urgency.
- Priority.
- Assigned team or person.
- Investigation performed.
- Resolution or workaround.
- User confirmation.
- Follow-up actions.
- Closure notes.

## Sample practice ticket: IT-1
| Field | Recorded information |
|---|---|
| Ticket key | IT-1 |
| Work type | Incident |
| Request type | Report a System Problem |
| Summary | Unable to connect to company VPN |
| Description | The VPN connection fails when I try to connect from my laptop. |
| Reporter | Supriya Thogu |
| Assignee | Supriya Thogu (assigned using Assign to me) |
| Priority shown | Medium |
| Status reached | Work in Progress |
| Internal note | Started investigating the VPN connection issue. |
| Actual technical resolution | Not performed; simulated workflow exercise |

## Reporting integrity
The sample ticket was not technically resolved. Do not record a root cause, fix, user confirmation, or resolution date unless those events actually occur. If the workflow is later completed for demonstration, clearly label any additional activity as simulated.
