# Incident Troubleshooting Procedures

## Purpose
This document provides a structured approach for documenting troubleshooting. It is a reusable procedure, not evidence that the listed checks were performed on a real system.

## General procedure
1. Read the incident summary and description.
2. Confirm the affected user, device, service, and time.
3. Ask for the exact error message if one exists.
4. Check whether one user or multiple users are affected.
5. Review known service alerts or maintenance notices, where authorised.
6. Follow approved support documentation.
7. Record each action and its observed result.
8. Escalate if the issue is outside the support team's access or expertise.
9. Confirm restoration with the user before resolving the ticket.

## Example scenario: VPN connection failure
**Sample ticket:** IT-1  
**Summary:** Unable to connect to company VPN.

Potential checks for a real support case may include:
- Confirm network connectivity.
- Check whether the VPN client is installed and running.
- Record the exact client error message.
- Confirm the user is following the approved sign-in process.
- Check service status or known outage notices.
- Escalate to the network or VPN support team when required.

Do not change security settings, disable protective controls, or request passwords. Follow the organisation's security policy.
